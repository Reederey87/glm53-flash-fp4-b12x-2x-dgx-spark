# Qualification — checkpoint × engine × kernel

Receipt: `receipts/qualification-<stamp>.txt` (regenerated by `./launch.sh qualify`).
This page records the reasoning and the pinning; the receipt is the evidence.

## 1. The checkpoint

`nvidia/GLM-5.3-Flash-FP4-Local@76348ddb` — `Glm5NextForConditionalGeneration`,
320B total / 18B active, hybrid sparse + linear attention (NoPE-MLA + KDA) with
manifold-constrained hyper-connections (mHC), native multimodal, 1M context.

Safetensors header totals: 165.7 GB of `U8` payload (packed FP4), 8.1 GB
`F8_E4M3`, 1.16 GB `BF16`, 1.16 MB `U32` (the compressed NVFP4 scale format),
352 MB `U16`. The model card is explicit that the **NVFP4 scale factors use a
new lossless compression format** that upstream vLLM did not support at release
and that a purpose-built container is required. That is the first compatibility
gate, and it is the reason the image — not just the flags — is pinned.

The checkpoint's seven storage classes (measured on the real bytes by the
earlier Flare kit, `tools/inspect_checkpoint.py`):

| Class | Share of bytes | vLLM path |
|---|---:|---|
| routed experts, NVFP4 + compressed scales | 94.9% | `--quantization modelopt_mixed`, `--moe-backend b12x`, `--load-format b12x` |
| per-block FP8 with F32 scales (`BlockFP8Weight`) | 2.9% | native |
| BF16 projections NVIDIA kept out of the FP4 path (`native-QB`) | 1.9% | native |
| vision tower | 0.2% | loaded, `--mm-processor-cache-gb 0` |
| unrouted | 0 | — |

No re-quantisation happens anywhere in this kit.

### Why Flare is not the deployment

1. **Preparation cost.** A package is a one-time, multi-hour, both-nodes-idle
   step producing ~178 GB. The head reports 187 GB free (95% full); the package
   would leave ~9 GB of headroom on a volume that also hosts the checkpoint and
   the images, which is below a safe reserve. Freeing the deposed EXL3 blob is a
   decision, not a script.
2. **Capacity.** Flare's own TP2 measurement for this recipe is ~1.1M KV tokens;
   this stack boots 2.35M on the same pair. For a 1M-context endpoint that is
   the difference between 2× and 1× full-context requests. (2.35M is the
   incumbent's boot figure and the number this kit reproduces; the 2× claim is
   pool-only — no 1M-token request has been exercised yet, see `spec/TODO.md`.)
3. **Maturity.** The vLLM path is the one NVIDIA's model card validates on
   `2 x DGX Spark 128 GB with 2M tokens of FP8 KV Cache`.

> Provenance: the Flare capacity, package size and preparation-time figures come
> from Flare's own TP2 measurement for its `glm53` recipe and from its
> documentation — they are **not** measured by this kit. The disk figures are
> measured live (`df` on the head, 2026-11-08). They are recorded to justify not
> booking a Flare window now, not as a benchmark result.

Flare remains the right second engine to qualify when a window can afford the
package; `spec/TODO.md` tracks it.

## 3. Kernel layer

- `b12x` is vendored in the image at
  `flashinfer/experimental/b12x`; `qualify.sh` imports the registry and counts
  ops (>30 expected).
- Image FlashInfer is **0.7.1 @ 91271757** (2026-10-15). The workspace clone
  (`local-inference-lab/flashinfer`) is at **361e45fad** (2026-11-01), 140
  commits ahead. The delta is kernel/planning work (PCIe gather profiles,
  split-K offsets, collective ladder search) — attractive, but it needs a full
  image rebuild because the vLLM fork's adapter surface is compiled against the
  packaged version. That is a separate window (`spec/TODO.md` #1), not a
  serving-window change.

## 4. Flag-level qualification

| Flag | Why it is in the recipe |
|---|---|
| `--attention-backend B12X` | upstream FlashInfer MLA rejects this checkpoint (`qk_nope_head_dim=256`, sm_121a); B12X is the sparse-MLA/KDA path |
| `--moe-backend b12x` | NVFP4 routed experts; `VLLM_B12X_MOE_FP4_FORCE_A16=1` keeps decode activations in 16 bits |
| `B12X_W4A16_A4_PREFILL=1` | A4 prefill path for the same experts |
| `--load-format b12x` | compressed-scale checkpoint loader (io_uring bounce on GB10) |
| `--quantization modelopt_mixed` | dense MLA/shared experts/router stay BF16/MXFP8; only experts are NVFP4 |
| `--mamba-cache-mode align --block-size 256` | KDA state alignment; 256 is the LCM page |
| `--kv-cache-dtype fp8 --kv-cache-memory-bytes 17G` | 2.35M tokens pinned, boot-to-boot deterministic |
| `--speculative-config mtp/5` | MTP-5 draft with humming MoE; measured acceptance is in the speed receipt |
| `VLLM_ENABLE_ROCE_ALLREDUCE=1` + 2 MB/16 MB caps | RoCEnante replaces NCCL on the decode path; prefill keeps NCCL above the cap |
| `--no-enable-flashinfer-autotune` | autotune warmup wedges GB10 on this stack |
| `--max-num-batched-tokens 4096` | larger batches were reported to wedge MoE warmup; 4096 is the proven point |
| `--enable-prompt-tokens-details` | required for `cached_tokens` in usage (prefix-cache evidence) |

Rejected in this window: `--async-scheduling` (not passed; default resolves per
build — measured in the gate), higher `gpu-memory-utilization` (0.90 passes
startup and wedges later), `moe-backend marlin` (W4A16 fallback, not this
checkpoint's fast path), KV pins above 17G (memory margin is 3–5 GiB).
